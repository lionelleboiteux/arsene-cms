## 0. Directory layout and module map

The suite is TypeScript + Vitest, run with `npm test` from the repo root — the
same toolchain, config shape and directory split as the sibling `pronos`
project, deliberately.

| Path | What it is |
|---|---|
| `tests/support/seams.ts` | The **single** place naming every production module the suite expects, with its expected signature. Every import is lazy, inside a function, so a missing module fails exactly one test. |
| `tests/support/fixtures.ts` | Deterministic fixtures; UUIDs match `contracts/openapi.yaml` examples. |
| `tests/support/imageFixtures.ts` | Real image bytes — a decodable JPEG, the same padded past 4 MB and past 20 MB, a decodable PNG padded past 4 MB, a corrupted JPEG, a PDF. Generated deterministically rather than committed, so no 20 MB blob enters git. |
| `tests/support/fakes.ts` | Fakes for the *collaborators* of a unit under test, so a handler test fails only because the handler is missing. |
| `tests/support/pg.ts` | Real Postgres 16 via Testcontainers + production-migration applier + seed helpers. |
| `tests/support/openapi.ts` | Loads Arsène's contract **and** the vendored pronos contract; builds Ajv 2020 validators from both. |
| `tests/support/prism.ts` | Prism mock lifecycle (consumer side, either document). |
| `tests/support/schemathesis.ts` | Schemathesis CLI runner (provider side). |
| `tests/unit/` | Pure-function domain tests, plus the real-codec image tests (fast, no DB, no browser). |
| `tests/telemetry/` | The 2 required events: shape + positive/negative emission. |
| `tests/db/` | Real Postgres: constraints, RLS, locking under real timing — and the seeded-DB public-site render pass. |
| `tests/contract/` | Both sides of Arsène's contract, plus the consumer side of pronos'. |
| `tests/e2e/` | The three journeys whose silent failure would be embarrassing. |

## 4. Telemetry events

Both events from the spec header's `required_events`. Shape, storage and both
emission directions are covered, because an event that only fires on success
cannot produce a completion rate — the denominator would be missing.

| Event | Shape test | Storage test | Positive emission | Negative emission |
|---|---|---|---|---|
| `draft_started` | `TELEMETRY-draft_started: builds a row carrying the writer, the article and the moment the draft started` (+ `a payload missing started_at is rejected…`) | `TELEMETRY-draft_started: the telemetry_events store accepts this required event type` | `TELEMETRY-draft_started: creating a new draft emits exactly one draft_started carrying the writer, the article and the start time` | `TELEMETRY-draft_started (negative): reopening an existing draft emits no second draft_started, so a crash-and-resume cannot reset the clock` |
| `article_published` | `TELEMETRY-article_published: builds a row carrying the writer, the article, the publish time and whether it was a republish` (+ `a payload missing is_republish is rejected…`, `a payload missing article_id is rejected…`) | `TELEMETRY-article_published: the telemetry_events store accepts this required event type` | `TELEMETRY-article_published: a successful first publish emits exactly one event, flagged as not a republish`; `TELEMETRY-article_published: republishing emits an event flagged is_republish…` | Four cases, one per way a publish can be refused: `DEC-01` (missing cover), `AC-08` (image not ready), `AC-05` (draft locked), `NFR-AUTH-01` (no bearer token) |

Registry guards, in code and in the `telemetry_events` check constraint:
`TELEMETRY-REGISTRY: the shipped registry lists exactly the two required event
types and no others`, `TELEMETRY-REGISTRY: an event type outside the agreed two
is rejected rather than silently stored` (unit), and `TELEMETRY-REGISTRY: the
store rejects an event type outside the agreed two…` (DB check constraint).

The end-to-end honesty of the pair is additionally proven against the real
Edge Function and real Postgres by `E2E-01` (both rows exist and the duration is
computable) and `E2E-02` (a refused publish writes **no** `article_published`
row).

## 6. Assumptions and flags for the product owner

1. **Lock staleness pinned at 90 s, heartbeat at 20 s.** ADR-0003 gives
   60–90 s and "roughly every 20 seconds". The suite pins the top of the range
   (`NFR-LOCK-02`). ADR-0003 itself says the number should be tuned after
   launch; changing it means changing one constant and one test.
2. **Autosave interval assumed 30 s** (`tests/unit/draft.test.ts`). AC-01 fixes
   only "over 30 seconds of typing", not the interval.
3. **Publish rate limit assumed 10 req/min/IP**, adopted from pronos'
   confirmed precedent via `02-architecture.v1.md` §7 (`NFR-RATE-01d`).
4. **Upload limit: contract's 20 MB, not the threat model's "e.g. 10MB".**
   `contracts/openapi.yaml` documents `413 FILE_TOO_LARGE` with
   `max_bytes: 20971520`; §7 says "e.g. 10MB". **These disagree.** The contract
   is a promise already made to callers, so the tests follow it — but this
   should be confirmed, not assumed, before green.
5. **The autosave indicator format** is `Last saved at HH:MM` in UTC, so the
   seam is deterministic; timezone rendering is presentation.
6. **`anon` / `authenticated` roles** are assumed to be created by the first
   migration, as pronos does, because the RLS tests `set role` to them.
7. **`draft_started` must be emitted server-side.** The editor creates drafts
   through PostgREST, not through an Edge Function, so a client-side emission
   could be lost by any client bug and the metric would silently lose its
   numerator. `E2E-01` asserts the event exists for an article inserted the way
   the SPA inserts one, which forces a trigger/RPC. **This is a design
   consequence of the metric being load-bearing; worth an explicit yes.**
8. **`NFR-TAMPER-01` assumes column-level privilege revocation** (SQLSTATE
   `42501`) rather than an RLS predicate that silently updates zero rows. Both
   satisfy the threat model; the test picks the one that fails loudly, since a
   silent zero-row update is indistinguishable from success to a client.

Added by the remediation pass **(v2)** — each of these is a choice this pass
made because nothing upstream fixed it, and each is cheap to change but
expensive to discover later:

9. **The draft routes are `POST /v1/articles` (create) and
   `POST /v1/articles/{id}/open` (reopen/lock).** `02-architecture.v1.md` §9
   requires a server-side seam and names the module, not the paths;
   `05-verification.v1.md` §4 probed three plausible paths and got 404 from all
   three. Reopening gets its own route rather than folding into create, because
   `409 DRAFT_LOCKED` is meaningful for one and impossible for the other.
   Neither route is in `contracts/openapi.yaml` yet — **the contract needs
   extending at green, or these paths need changing to whatever it says.**
10. **The elevated database role is called `service_role`**, Supabase's own
    name for it. `db/migrations/0001_initial_schema.sql` creates only `anon`
    and `authenticated`, so a new expand-only `0002_*.sql` must create it and
    grant it INSERT (`NFR-GRANT-01` asserts the behaviour — an insert that
    succeeds — not a particular grant statement, so a policy-based
    implementation satisfies it equally).
11. **Supabase access tokens are HS256, signed with the project's JWT secret.**
    That is how Supabase Auth issues them today; the tests mint the same shape.
    If the project is ever moved to asymmetric signing keys (RS256/JWKS), these
    tests pin the wrong algorithm and must change with it.
12. **The upload rate limit is assumed to be the same 10 req/min/IP as
    publish** (`NFR-RATE-02`). Nothing states an upload-specific number; using
    a different one is fine, but it should be a decision rather than a default.
13. **The Lambda status callback carries its own secret in a request header,
    checked before anything is read from the database.** ADR-0004 fixes that it
    must be a distinct, independently rotatable secret; the header name is this
    pass's choice.
14. **HEIC decoding depends on the `sharp` build.** `sharp@0.34.4`'s prebuilt
    binary on this machine (macOS arm64, libheif 1.20.2) decodes HEVC-in-HEIF,
    so `AC-07/D7-heic` is a real test here. It ships an AV1 *encoder* only, so
    the fixture is committed rather than generated. **If CI runs a `sharp`
    build without an HEVC decoder, that one case will fail for an environment
    reason rather than a product one — check it on the CI image before
    treating a failure there as a regression.**

Added by the third remediation pass **(v3)**:

15. **Legacy static-token mode must be opted into explicitly, not inferred
    from a missing secret** (`NFR-FAILCLOSED-01`). `router.ts`'s `verify()`
    already documents running without a JWT secret as legitimate for
    "deployments configured without a JWT secret at all (and the pre-JWT
    end-to-end suite)", so the fix for M3 cannot be "always require
    `SUPABASE_JWT_SECRET`". The shape this pass chose: `serverMain.ts` — the
    deployable entry point M3 names — refuses to start when
    `SUPABASE_JWT_SECRET` is absent *or empty* unless
    `ALLOW_LEGACY_STATIC_AUTH=true` is present in its environment, and
    `server.ts`'s `startServer()` forwards a new
    `ServerOptions.allowLegacyAuth === true` as that variable (via `env`,
    never argv, exactly as it already forwards the two secrets). The check is
    deliberately **not** in `startHttpServer()`: that is a library entry point
    taking its configuration as arguments, where omitting a secret is already
    the caller's explicit choice; the silent-downgrade risk lives in
    environment variables going missing. `tests/e2e/publishJourney.test.ts` and
    `tests/contract/provider.schemathesis.test.ts` — the pre-JWT suite — were
    given `allowLegacyAuth: true` in their setup (no assertion touched) so the
    legitimate mode stays legitimate and stays visible at the call site.
    **This is a mechanism choice, not a bug fix: change it freely, but change
    the test with it, and keep "chosen" distinguishable from "arrived at".**
16. **The router exposes a configurable read timeout with a bounded default**
    (`NFR-DOS-03`/`03b`): `RouterOptions.readTimeoutMs` overrides it (so the
    test proves the mechanism in ~2 s rather than waiting out a realistic
    value) and an exported `DEFAULT_READ_TIMEOUT_MS` is what production gets.
    NFR-DOS-03 accepts any way of letting go — an explicit response, a Node
    `408`, or the socket being torn down — because the finding is about
    unbounded waiting, not about a particular status code (and the closed
    `Error.code` set in `src/api/http.ts` has no timeout member; adding one is
    a contract change, so it was not assumed).
17. **`NFR-CALLBACK-04` places the CDN-origin check in `router.ts`'s
    `ImageStatusBody` schema**, where the `CDN_ORIGIN` constant already lives —
    i.e. at validation time, before any repository call. The test proves that
    placement rather than merely the outcome: it runs against a server whose
    database is unreachable, so only a rejection decided from the body alone
    can produce a `400`. `handleImageStatusCallback`'s own contract, and its
    unit tests, are unchanged. A `startsWith(CDN_ORIGIN)` implementation is
    not sufficient — `NFR-CALLBACK-04b` is exactly the host that defeats it.

## 7. Deliberately not covered, and why

| Not covered | Reason |
|---|---|
| **The counter-metric ("writer adoption must not decline")** | `02-architecture.v1.md` §8 flags this explicitly: reverting to Word/Docs happens entirely outside Arsène, so **no event can observe it** and none was invented. The agreed proxy is a manual weekly published-article-count-per-writer review at John's gate. **This is a real, named gap, not an oversight — Pam and the product owner should confirm the proxy is acceptable.** |
| Elevation of privilege (§7) | The threat model marks it **N/A**: every writer has equal, full publish rights and no approval step exists to escalate around (spec §2, §8). There is no behaviour to assert. |
| Real Cloudflare Pages/Workers ISR revalidation | The revalidation call is asserted at its seam (`AC-17: publishing triggers on-demand revalidation…`, `NFR-OBS-01`), with the transport faked. Proving Cloudflare actually purges is a deploy concern for John's pipeline gate, not a unit under test here. |
| Rollback timing ("seconds to promote a previous deploy") | §6 says this is to be **measured and rehearsed at the pipeline gate**, not estimated. Not a test. |
| Cost / free-tier limits (§4) | Not behaviour — with one exception: the *egress design constraint* is behaviour, and is covered as `NFR-EGRESS-01`. |
| Browser/DOM rendering of the editor | Out of scope for this gate by the architecture's own testability assessment: paste sanitization is asserted at the pure-function seam that the editor must call, and the public site at the render-pass seam. No Playwright-class test exists in this suite; if one is wanted for the editor shell, it belongs to a later gate and should be argued for on its own merits. |
| Out-of-scope spec items (ads/monetisation, Wix migration, affiliate blocks, approval workflow) | Spec §8. The *absence* of an approval step is asserted positively rather than left implicit — `AC-17` and `E2E-03` both publish straight to live with no intermediate state. |
| pronos' side of the fixture contract | Arsène is purely a consumer; verifying the real pronos deployment satisfies `getCurrentGameweek` is pronos' provider-side responsibility (`contracts/pronos-fixtures.consumer.md` §6). Arsène's tests never touch a live pronos. |
| Real content quality of generated alt text / meta / advisory copy | The seams assert derivation from the article's own context (`AC-15`, `AC-13`, `AC-16`), not the eloquence of an LLM's wording, which is not a testable commitment. |
